# Pixelmon服务器：配置怎么选、机器在哪买，一份照着做就能开服的清单

搜 Pixelmon服务器的人，最后基本都卡在同一个地方：版本对不上、内存不够、机器不知道从哪买。这三件事里，前两件是技术问题，第三件是钱的问题，但它们互相咬得很紧——配置选错了，钱花了照样卡。

这篇按实际开服的顺序讲：先把版本对齐，再算内存和 CPU，然后才是买哪台机器、花多少钱。

## 先把版本对齐：Java 和加载器错了，服务器连启动都不给面子

Pixelmon 目前的主线是 9.3.x，跑在 Minecraft 1.21.1 上，加载器用的是 NeoForge，不是 Forge。这跟你在中文社区看到的大部分教程都不一样——那些教程大多还停留在 1.12.2 + Forge 的时代。9.3.0 开始官方切到 NeoForge，也没有把改动回溯到旧版本，所以 1.16.5 和 1.12.2 的老存档只能继续待在自己的版本线里，别混着改。

| Minecraft 版本 | Pixelmon 版本 | Java 版本 | 加载器 |
| --- | --- | --- | --- |
| 1.21.1 | 9.3.0 – 9.3.13 | Java 21 | NeoForge |
| 1.20.2 | 9.2.4 – 9.2.10 | Java 17 | Forge |
| 1.16.5 | 9.1.x 及更早 | Java 8 | Forge |
| 1.12.2 | 8.1.2 | Java 8 | Forge |

还有一条容易被忽略：**玩家客户端的 Pixelmon 版本必须和服务端完全一致**，差一个小版本就会在进服时收到 Mod Rejection，人根本进不来。Java 版本不匹配的典型症状是启动直接崩，或者在控制台里抛 `UnsupportedClassVersionError`——看到这个报错，基本就是 Java 比模组版本老了。

## Pixelmon 到底要吃多少内存和什么 CPU

官方 Wiki 现在的说法是至少分配 4GB 内存，人多了再加（中文页面里针对 1.12.2 的那一节写的是 3GB，老版本确实更轻）。海外几家托管商给的区间更细：

| 同时在线人数 | 偏低配置 | 舒服的配置 |
| --- | --- | --- |
| 2 – 6 人 | 4GB | 6GB |
| 6 – 10 人 | 5GB | 8GB |
| 10 – 15 人 | 6GB | 8 – 10GB |
| 20 人以上 | 9GB | 12 – 16GB |

有个判断挺有用：Pixelmon 是单个大模组，不是那种挂了 200 多个模组的整合包，所以内存曲线比 ATM9、RLCraft 那一类好估算。真正吃资源的是野怪实体——每个玩家身边都在触发刷新，人多还分散在地图各处探索的时候，内存和 CPU 会一起往上冲。世界跑得越久、被探索过的区块越多，占用也会慢慢涨上去，这跟"刚开的新服"完全是两个状态。

CPU 这块要看单核而不是核心数。野怪刷新、战斗结算、区块生成这些活儿，很多是单线程跑不完就得等的，一台核多但主频低的机器开 Pixelmon 会很难受，10 人以上尤其明显。

## 家用电脑开服还是租一台：把隐性成本算清楚

自己电脑开服理论上免费，实际要过几道坎：公网 IP（多数家宽已经是内网 IP，得靠内网穿透）、路由器端口映射、机器得一直开着、再加上电费。几个朋友周末玩一下还行，一旦变成"随时有人想上就得上"，家用方案就开始别扭了。

租服务器省掉的就是这些：自带公网地址、不用管端口映射、机房带宽稳定、重启和换配置在面板上点几下。代价当然是月租。

## 机器到手之后：以 NeoForge 1.21.1 为例的实际步骤

1. 装系统时就选 Linux（Debian 或 Ubuntu 都行），别用 Windows——同样的机器，Windows 本身会多占掉一部分内存。
2. 先用 NeoForge 1.21.1 的服务端把机器启动一次，按提示接受 EULA。
3. 停服，**把这次生成的默认世界删掉**。目的是让 Pixelmon 的建筑和群系在真正的第一次开局时就出现在出生点附近，而不是等你跑出去几百格才遇到。
4. 上传 Pixelmon 的 `-server` jar 到 `mods/` 目录。注意用带 `-server` 后缀的那个（大约 43MB），不要用 400MB 左右的 universal 版本，也不要解压或者改名。
5. 重新启动，看控制台加载完成为止。
6. 玩家端装对应的 Pixelmon 版本、NeoForge 1.21.1 和 Java 21，然后用服务器公网 IP（或映射的地址）加进去。

一个现实变化：Pixelmon 现在已经不在 CurseForge 上发布服务端整合包了，最后一个带服务端包的是 2026 年 1 月的 9.3.14，更新的版本都得按上面这样手动上传。所以别指望"一键安装"能包办，做好手动摆文件的准备。

## 上线之后最容易踩的几个坑

- **Java 版本装错**。这是启动失败的第一大原因，9.3.x 必须要 Java 21，先用 `java -version` 确认一遍再排查别的。
- **探索时突然卡住或者崩服**。多半是内存吃紧。Pixelmon 提供了很直接的控制项：`config/pixelmon/spawning/wild.yml` 里的 `entities-per-player`（每个玩家身边最多刷多少只）和 `maximum-spawned-pokemon`（全服上限），`general.yml` 里的 `player-tracking-spawner-spawn-collection-rate` 调高也能减轻刷新压力。
- **配置文件改错地方**。网上很多教程让你改 `pixelmon.hocon`，那是 Pixelmon 8 时代的做法。现在 9.x 的设置分散在 `config/pixelmon/` 下的多个 yml 文件里，改完重启服务端生效。
- **没做备份**。玩家抓到的精灵、练的等级、箱子里存的都在这份存档里，丢了就是真的丢了。把世界文件夹和 `config/pixelmon/` 一起做定期备份。

## 固定计费还是动态计费，按你每天玩多久来定

> 每天稳定在线 2 小时以上，选固定计费；只有碎片时间偶尔上去玩，选动态计费。

逻辑很简单：固定计费就是每月固定租金，跑满不额外花钱；动态计费基础月租低，但 CPU 用超的部分按天结算。你要是每天下班准时开服三四个小时，动态计费最后不会比固定便宜。

第三，注意退款窗口。7 天无理由退款每个账号限 3 次，够你试错两三种配置了，但别把试用额度浪费在"随便点一台看看"上——先按人数把配置定下来再下单。

Pixelmon 服务器这件事，真正难的不是技术，是在"内存够用"和"月租别太贵"之间找一个你愿意长期维持的平衡点。版本对齐、单核优先、内存按人数留余量，这三条做到了，剩下的就是挑个延迟合适的机房。
